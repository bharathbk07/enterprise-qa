# Contributing

Thank you for helping improve Enterprise QA Agent Kit. Start with the README, shared contracts and the specific skill or runtime component relevant to your change.

## Before changing behavior

Search existing [issues](https://github.com/bharathbk07/enterprise-qa/issues). Open a focused proposal for large architecture changes, new host integration, custom MCP servers or changes to approval/privacy rules. Include the problem, expected behavior and proposed scope. Do not add live credentials or production evidence to an issue or patch. Security-sensitive reports follow SECURITY.md rather than public issue templates.

## Development setup

Use Python 3.11+ and Node.js 22+. Install recorder dependencies and Chromium as described in docs/GETTING-STARTED.md. Work on a branch in your fork or an authorized repository checkout. Use local fixtures or an explicitly approved sandbox; routine contribution checks must not query production, launch load or write external issues/pages.

## Source and generated files

Edit canonical definitions under skills/, agents/, contracts/ and docs/. Keep each skill and agent focused. Shared reference copies, platform agent exports, skill/agent LICENSE copies and distribution.json are generated by scripts/sync_package.py. Change the canonical source first and include regenerated files in the pull request. Do not edit generated copies alone.

After reviewing intentional source changes, run:

```sh
python3 scripts/sync_package.py
python3 scripts/validate.py
npm --prefix recorder run build
python3 -m unittest discover -s scripts -p 'test_*.py'
npm --prefix recorder test
```

Run checks appropriate to the change; report any skipped checks and the reason. Add regression coverage for behavioral bugs or sensitive artifact handling. Documentation-only changes need relevant link/metadata checks rather than invented runtime test claims.

## Preserve project behavior

- Browser work uses a dedicated spawned QA-owned process; no integrated browser or personal/shared session attachment.
- Default clarification is one combined flow review, with essential follow-ups only. Preserve named illustrated flow documents and confirmed preference scope.
- Keep current-version manual execution gates, explicit approval boundaries and truthful evidence classifications.
- Do not weaken production redaction, output path boundaries, resource budgets or user-edit protection.
- Discover actual MCP capabilities; never claim templates are live integrations or unsupported editions are supported.

## Pull requests

Describe the concrete problem, resulting behavior, validation and limitations. Keep scope reviewable; link the issue when available. Mark generated files and changed platform assumptions. Provide only synthetic/redacted fixture evidence. Follow the pull request template and community conduct guidance.
