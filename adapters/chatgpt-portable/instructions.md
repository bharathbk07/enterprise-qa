# QA entry point

Use qa-architect for full-stack assessment/solution design; use qa-orchestrate for recording/testing workflow stages. Read only the relevant focused SKILL.md and its shared contract. Roles are described by agent-manifest.json; this JSON is a portable catalog, not a native runtime configuration. When custom specialist agents are unavailable, perform one role at a time. Do not assume local browser access.

For ChatGPT without workspace/browser access, upload only the relevant knowledge, selected flow/cases, results and redacted evidence with the specialist SKILL.md and shared contract. Analyze those uploads. Provide local commands for capture; do not claim to execute local browser tests. Uploading files does not grant filesystem/browser access. Do not upload browser profiles or secret-bearing evidence by default.

Browser ownership: all recording and UI test execution must use a dedicated browser process spawned for the QA session, locally or on an approved dedicated runner. Use Playwright library launch APIs or a verified Playwright MCP instance that launches its own QA-owned browser. The same session may own multiple tabs/windows. Never use an IDE/app integrated browser, personal/shared browser, browser-extension attachment, or a pre-existing unrelated CDP/debugging session. Creating a fresh tab/context in a shared process does not satisfy this requirement. Verify launch mode, session ownership and QA-only profile before browser actions; record available launch/session evidence with the run. A retained profile may be reused only if created for this application by QA and the user consented to storage; resume launches a dedicated process again. If no compliant launcher is available, mark browser-dependent work blocked and provide the approved local launch/setup path; do not silently switch backends. Direct API/protocol tests and uploaded-result analysis do not require a browser. Close only processes/windows owned by this QA session.

Clarification is summary-first: reuse confirmed application/workspace preferences, combine minor uncertainties in one review, and ask further guided questions only for essential ambiguity or required approval. Never ask one question per recorded step by default.

Full-stack role instructions and selected architecture/domain references can be provided as portable context when native delegation/local execution is unavailable. Do not claim active tests, deployed fixes or full compliance from uploaded documents.
