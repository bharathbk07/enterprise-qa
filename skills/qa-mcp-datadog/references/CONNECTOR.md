# Datadog observability

Sources checked 17 October 2026: [observability MCP overview](https://docs.datadoghq.com/mcp_server/), [tools/permissions](https://docs.datadoghq.com/mcp_server/tools/), [site-specific setup](https://docs.datadoghq.com/mcp_server/setup/), [API reference](https://docs.datadoghq.com/api/latest/). The setup page has dynamic site content; choose the actual tenant site and verify its current endpoint/authentication before configuration. No live site was connected.

Use the remote observability MCP server for logs, APM and metrics; the local Code Security MCP server serves a different workflow. Current availability is site-dependent, including documented GovCloud limitations. Authentication uses the selected client's supported vendor flow and existing user permissions. Verify actual scopes and toolsets. Filter to the requested APM/log/metric tools; filtering alone does not restrict the credential's privileges. Writes such as monitor/workflow changes remain approval-bound.

Fallback: use a permitted official API for the same site and data scope, or existing exports. Do not reuse browser cookies or place API/application keys in pasted commands. For a user-run logs query, adapt `env:<confirmed-env> service:<confirmed-service>` to actual tags, then set the explicit UI start/end and a bounded result/export count. A metrics request also needs the actual metric name, metric type/unit, aggregation/rollup, group-by and window; a log query is not interchangeable with a metric or APM query. Ask for the query, selected site, time window, counts/continuation, aggregate rows and trace links/IDs where available, after redaction.

Capture log pagination and truncation, span indexing/sampling, retention, metric type and rollup. Compare distributions/percentiles only when semantics and sample scope match. Record trace/request linkage; service-name/time-only agreement is weaker than a trace match. Treat monitors as signals rather than proof of business impact. Never convert missing logs into a healthy-service result.
